接続されていたのは JAPANNEXT 製 1 台と BenQ 製 2 台（EW3280U、EX3210U）だが、どの DISPLAY 名がどの製品かは記録していない。
確認の後に、利用者が設定の「ディスプレイ」で 3 台とも HDR がオフであることを確認した。確認中に HDR の設定を変えた記録はないため、3 台とも SDR で確認したとみなす。

大きさと位置は高 DPI に対応していない PowerShell から読んだ値で、Windows が換算した座標である。

### 方法

開始時刻を確認の約 2 時間前、移行時間を 240 分、復帰時刻を 18:00 にして自動切替を有効にし、確認の間は白黒度が約 50〜67% の移行中になるようにした。
色行列は、別のプロセスから Magnification API の `MagGetFullscreenColorEffect` で読み戻した（`scripts/color-effect.ps1`。Windows PowerShell から `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\color-effect.ps1` で実行する）。
このスクリプトは、確認の最中に使った補助スクリプトを整理したもので、整理した後に `Read`・`Same`・`Other` の動作を同じ PC で確かめた。
アプリの行列では先頭の要素が `1 - p + 0.2126p` なので、そこから白黒度 `p` を計算し、時刻から求めた値と比べた。
各モニターの見た目と通知領域のメニューの状態表示は、利用者が見て報告した。
利用者がメニューを見た時刻と API を読んだ時刻は、数十秒から数分ずれている。白黒度は確認の間に 1 分あたり約 0.4% ずつ上がるため、表の 2 つの列の値は一致しない。
例えば拡大縮小を変えた行のメニューの 61% は変更の直後（11:40 ごろと推定）に読んだ値で、API の 0.627 は 11:44 に読んだ値である。
API の読み戻し値は画面全体に 1 つで、モニターごとの値はない。モニターごとの結果は利用者の観察による。

### ほかのアプリの色変換との競合

ほかのアプリの代わりに、`scripts/color-effect.ps1 -Action Other -HoldSeconds <秒>` で、緑と青を 80% にする色行列を `MagSetFullscreenColorEffect` で書き込み、指定した秒数だけ保った。
スクリプトが終了すると、色行列は単位行列に戻った。終了時の `MagUninitialize` かプロセスの終了で解除されたと考えられる（推定）。

| 操作・条件 | API の読み戻し値 | 利用者が見た結果 |
| --- | --- | --- |
| アプリがグレーを適用している間に、スクリプトから書き込む | `MagSetFullscreenColorEffect` が FALSE を返して失敗した。読み戻した値をそのまま書き戻す操作（`-Action Same`）も失敗した。色行列はアプリのグレーのまま | — |
| アプリを停止して単位行列にした後、スクリプトから書き込む | `-Action Same` と `-Action Other` の両方が成功した | — |
| スクリプトが行列を保っている間に、設定画面で自動切替を有効にして保存 | スクリプトの行列のまま | 3 台ともグレーにならず赤みを帯びたまま。メニューは「競合のため停止。ほかの画面の色変更を確認してください。」 |
| スクリプトの終了後 | 単位行列 | 3 台ともカラー。メニューは競合のまま |
| 「自動切替を再開」 | 読み取っていない | 3 台ともグレー。メニューは「移行中・白黒度67%」 |
| 競合中に右のモニターを設定で切断し、再接続 | 切断中も再接続後も、スクリプトの行列のまま | メニューは「競合のため停止」のまま |

この結果から、アプリは画面構成の変更の後もほかのアプリの色変換を上書きしなかった。
一方、アプリがグレーを適用している間は、別のプロセスからの書き込みが API に拒否された。
したがって今回の環境では、アプリの適用中にほかのアプリが色を変える状況は作れず、競合はアプリが適用していない間に起きたものだけを確認した。
失敗の理由は確認できていない。確認時の補助スクリプトは失敗の後に `GetLastWin32Error` で 87（`ERROR_INVALID_PARAMETER`）を読んだが、この API がエラーコードを設定するとは文書化されておらず、成功した呼び出しの後にも 0 以外の値（203）が読めたため、87 を失敗の理由とはみなさない。

| --- | ---: | ---: |

この読み手の負担の増減はツールでは測れておらず、別途コードを読む人による評価が必要である。
